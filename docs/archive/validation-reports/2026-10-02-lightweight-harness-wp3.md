# WP3 — Direct inspection and atomic edit intents

Date: 2026-10-02. Exact library: 0.8.4. Parent milestone: `e8c9aaa`. Status: completed locally; release gates remain below.

The model now has two declarations: `inspect_document` and `apply_document_edits`. The compiler accepts explicit desired text, comments, and basic inline formatting against fresh opaque handles. It validates the complete proposal before library preparation, resolves every handle from one fresh capture, and submits one atomic canonical operation array. No mutation executor asks another model to interpret the request. A compact versioned guide replaces the large tool prompt. Former tool names return structured refusals.

Every actual batch owns an exact-source checkpoint before its content insertion. Checkpoint failure or source change prevents that insertion. Preparation must account for every operation; the receipt accounts for every intent, including verified no-ops. A successful content insertion is followed by fresh canonical accepted-text/structure/comment verification and pure no-op verification of requested formatting. A host or verification failure after an attempted write stops the loop without replay. Cancellation preserves settled write evidence. The checkpoint control is retained in the Word UI.

The loop rejects multiple mutation calls and mixed inspect/mutate exchanges before executing any call. It pairs all function responses, preserves the six-turn/two-failed-mutation budgets, bounds stale recovery, and replaces a fabricated success after an unresolved refusal with the observed result. Recovery accepts a complete JSON call for declared names; the retired regex reconstruction branches are gone.

The first actual direct Word replay completed all 16 prompts but refused every retained edit as stale. Captured before/after parts showed Word regenerating `w:rsid*` editing-session metadata, settings `w:rsids`, and the ID of its extra empty export paragraph on unchanged reads. Every other transported part was identical. These session identifiers are distinct from tracked-change IDs ([Microsoft Open XML reference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.rsid?view=openxml-3.0.1)). This is a Word transport identity issue in the application; it is not an engine failure or reason to weaken target descriptors.

The fix computes the public revision token over a derived copy with only those confirmed volatile fields normalized. Word also regenerates the same session attributes in comment paragraphs after a comment is created; normalization covers these Word XML attributes without discarding comment content, IDs or authors. The original source and insertion payload remain intact. A Word paragraph count captured with `paragraphs.load('$none')` in the same sync certifies the one extra empty export paragraph; its ID is normalized only when that count and canonical structure agree. This loads collection membership without reading paragraph properties ([Microsoft example](https://learn.microsoft.com/en-us/javascript/api/word/word.listitem?view=word-js-preview)). Export-only paragraphs receive no edit handles, and the end handle targets the last real paragraph. Text, styles, numbering, relationships, meaningful paragraph IDs, tracked-change IDs/content/authors, comments, and other transported dependencies remain covered. The immutable engine preparation still uses its own raw public revision token.
