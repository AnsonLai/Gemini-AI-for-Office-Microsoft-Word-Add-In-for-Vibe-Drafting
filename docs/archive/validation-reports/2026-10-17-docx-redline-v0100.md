## What changed

- **Revision policy.** Plain-text `replace_text` and `rewrite_paragraph` operations send `existingRevisions: 'auto'`. The library slices around another or unattributed reviewer's pending revisions and merges the user's own. This replaces the add-in's per-paragraph author check.
- **Verification.** The post-commit check compares the committed body with the prepared package through the library's `compareDocumentInspections`, replacing the local `acceptedShape`/`reviewSegments` comparison.
- **KB-5.** The `TRACKING_POLICY_MISMATCH` guard is removed. The library refuses the same case itself (`UNTRACKED_CREATED_REVISION`).
- **KB-7.** 0.10.0 keeps literal underscore runs (CommonMark flanking), and a caller's `structuredContent: false` keeps inline Markdown literal. The "Add Date Row" known-defect gate is removed, and the case asserts strictly.
- **Word layer.** `consumer-core.js` and `word-source-identity.js` stay in the plugin (owner decision: the library stays host-independent). They now parse and serialise through the root `parseOoxmlSafe`/`serializeOoxml` instead of `adapters/xml-adapter.js`.
- **Library behaviour changes the add-in doesn't depend on:** unattributed revisions count as another author's (`EXISTING_REVISIONS` instead of `UNSAFE_REVISION_NESTING` under `merge-same-author`), and comment replies avoid body `w14:paraId`s. The add-in maps neither error code.
