# Release v2.2.0.0

Releases are reflected in the commercially available version on the Microsoft Marketplace at:
https://marketplace.microsoft.com/en-ca/product/saas/wa200009707

## Key Changes

**Updated docx-redline-js:** Gemini AI for Office now uses `@ansonlai/docx-redline-js` version `0.8.4`, keeping the Word add-in aligned with the shared DOCX redline engine.

**Lettered and line-broken text:** Text typed as "A. …", "B. …" on separate lines (with Shift+Enter breaks) can now be turned into a real A, B, C list, and individual words in such paragraphs can be edited without disturbing the line breaks or turning the paragraph into a list.

**Remove formatting:** Requests such as "unbold BC in governing law" now work. Bold, italic, underline or strikethrough can be added to or removed from a specific phrase, including one that appears more than once in a paragraph, as a tracked formatting change.

**Edits after a table is created:** The assistant now sees the document exactly as the edits will apply to it, so text pending deletion (for example the paragraphs a new table replaced) no longer confuses later edits.

**Bullets in rewrites:** Bullets added while rewriting a provision are real bullets rather than continuing an existing numbered list.

**Formatting with tables:** Underlining or bolding text in the same request as adding a table is now supported, and existing formatting is kept when a table is appended.

**More forgiving targeting:** Edits are no longer rejected when the assistant writes a straight apostrophe or quote where the document uses a curly one.

**More faithful tracked changes:** Paragraph insertion and list-range replacement now reject cleanly, preserving the original paragraph boundaries, empty list items, and list numbering. Hyperlink punctuation and manual line breaks also retain their original placement when changes are accepted or rejected.

**More reliable editing tools:** List and table commands validate their targets and inputs before editing. Supported redline batches check their source document context and refuse stale targets, while clearer operation results distinguish successful edits from failures or uncertain Word writes.

**Better multi-step chat edits:** When a request needs several editing steps, the add-in now refreshes its view of the document between steps. Failed edit attempts are limited, so a request stops with a clear message instead of retrying endlessly or leaving the spinner running.

**Recovery from outside changes:** If the document changed after the add-in read it, the add-in refuses the affected edit before writing, then refreshes its view once and replans. If the edit still can't be applied safely, it stops with a clear message.

**Final paragraph plus table:** Editing the last paragraph and appending a table in the same request is now handled together.

**Faster startup:** Editing support loads when first needed, reducing the add-in's initial JavaScript payload.

**Expanded quality checks:** Automated regression coverage now includes real Microsoft Word and Office.js validation of tracked changes, list numbering, formatting preservation, and Accept All/Reject All behavior, plus a 16-request end-to-end editing session on a sample NDA that runs in desktop Word.

**Shared redline engine:** The document reconciliation engine continues to live in its own reusable package:
[https://github.com/AnsonLai/docx-redline-js](https://github.com/AnsonLai/docx-redline-js)

## Known Issues

**Word Online:** Word Online continues to be slow and unreliable when running many commands or a long task.

**Changing text you just formatted, plus a table:** If a paragraph already has your own pending formatting change (for example an underline you just added) and one request both rewrites that paragraph's text and adds a table, the request is refused before anything is written, because the formatting would be lost on Accept All. Make the text edit and the table as separate requests. A fix is pending in the shared redline library.

**Reject All after a tracked table append:** Rejecting all changes after a tracked table append at the end of a document can leave one extra blank paragraph. A fix is pending in the shared redline library.

**Author name on some edits:** Adding a table row, inserting a deeply nested list item, and converting numbered headings into a list still use Word's own editing commands, so Word records those tracked changes under the Office user name instead of the redline author set in the add-in.
